# Source-backed continuation with judgment checkpoints

This continuation adapts the pinned published Columbo experimental review procedure. It does not change collectors, thresholds, exclusions, suppressions, stage membership, exit semantics, tests, dependencies, or required behavioral contracts. Its deliberate protocol change is that time/cycle/failed-approach thresholds request supervisor judgment rather than automatically ending an intervention. Preserve the published frozen historical instructions unchanged; this file is a separately versioned continuation policy.

## Before work

Freeze exact original and starting endpoint source identities, protected tests/oracles, tool and dependency pins, actual environment, full-suite command, external characterization command, staged and ordinary scan commands, and evidence destinations. Original sources and oracles remain untouched. Capture active source identity at every invocation. Record prior failures and cumulative costs from the earlier run; a continuation, repair, worker replacement, or checkpoint never resets them. Keep preparation, queue, execution, source-inspection/intervention, and validation costs distinct. Report available usage only, never invented tokens or costs.

Maintain a live inventory of every initial eligible evidence ID, semantic family, phase, characterization obligation, current disposition and next hypothesis. Keep newly added and removed evidence separately. Distinguish reviewed retention, attempted unresolved work, and work not yet reached. Record each source-backed reason and each actual attempt, including compilation and fixture failures. Name the observable behavior boundary before edits and characterize unchanged behavior with useful assertions that run unmodified at the changed endpoint. New-helper-only tests are supplemental.

## Generic phase assignment

1. Untangle behavior: inspect full source context of every eligible initial ID and relevant collaborating sites. Investigate repeated execution/decision protocols by shared knowledge and next-change cost. Preserve intentional behavior, order, mutation, failure and lifecycle differences.
2. Assign ownership: investigate supported ownership evidence and available non-gating review leads. Favor evidence of coherent responsibility over pattern names or score reductions.
3. Consolidate shared responsibility: inspect every eligible duplicate group even if earlier findings remain or tool stages are clear. Share responsibility only when contracts and change pressures align; preserve meaningful repetition.

Review may progress once current-phase IDs have honest dispositions. Tool stage clearance still follows actual Columbo gates. Locked stages remain locked and retained/unresolved findings remain findings. Complete ordinary and staged snapshots are required; visible active-stage output alone is incomplete evidence. Independent source-only reviews remain blind to intervention identities, scan scores, worker hypotheses and other reviewers' recommendations. Give independent reviewers no intervention rubric or score targets. Never give workers independent reviews as targets or feedback during intervention.

## Checkpoint triggers and decisions

Reach a checkpoint at the planned time/cycle threshold, repeated unproductive attempts, two materially different unsuccessful approaches, a phase transition, a proposed scope change, an essential prerequisite failure, or a validation regression. Do not treat unfamiliar behavior as automatically blocked. Attempt concrete characterization first, or identify the exact indispensable missing prerequisite and why no safe local oracle is available.

Every checkpoint must contain:

- Cumulative timing and cost from original start, including prior failures, preparation, queue and active execution; available resource headroom and remaining validation work.
- Exact endpoint/source/oracle identities and command receipt references.
- Actual attempts since last checkpoint, hypotheses, observations, results and negative/inconclusive evidence. Name what was learned rather than counting activity as progress.
- Current validated endpoint, pending/unvalidated edits, full-suite and focused-test outcomes, actual scan exits, verified SQLite validity, stage/ordinary verdicts and locks.
- Live inventory with remaining opportunities and unfinished obligations; distinguish evidence-backed retention from not reached.
- A source-backed comparison of the strongest open residual costs in changed families and the strongest untouched opportunities. Status labels must not exclude a concrete unresolved cost from actual priority selection; preserve cohesive retentions and validated partial gains.
- One next falsifiable step, predicted distinguishing outcomes, required resources and how the result changes the decision.
- Explicit supervisor decision: CONTINUE, REDIRECT, or BLOCK, with reason and next review condition.

CONTINUE when validated design improvements or concrete characterization learning support another useful step. Safely extend productive runs and reserve at least the planned validation allowance (initially 15% of the revised total window, increased if measured validation requires more). Do not squeeze validation out to satisfy a nominal deadline. An extension records old/new allowance and reason; cumulative cost remains unchanged.

REDIRECT when repeated unsuccessful approaches add no new evidence. Change hypothesis or characterization boundary, replace a stalled worker, or diagnose tools/resources rather than endlessly repeating a failing command. Keep every failed attempt visible. No production edit is required to justify progress.

BLOCK only for an exact essential authorization, product, safety or resource prerequisite requiring input. Name the minimal next action or prerequisite. An exhausted local queue is not an overall terminal BLOCK while material endpoint costs remain: inspect broader source and correctness evidence, diagnose collector, phase or worker gaps, and REDIRECT. Terminal completion requires a meaningful endpoint supported by independent source review and correctness evidence; otherwise continue or redirect unless an exact essential prerequisite requires input. For evidence uncertainty, prefer bounded characterization over a blanket blocked label. A genuinely invalid endpoint cannot be accepted; preserve its diff/failures and return to the last validated endpoint when authorized. Never discard evidence while restoring code.

## Validation and completion

Small changes receive frozen full tests plus fresh staged and ordinary analysis, with focused external characterization before/after. A full-suite pass alone is not equivalence proof. Never weaken protected tests, hide syntax, tune gates, or require zero findings. Reserve validation time by extending productive work safely; supervision controls continuation, not tool verdicts.

An invocation receipt is transport/execution evidence only. Accept scan evidence only after checking actual child exit, expected SQLite file existence, integrity, schema/version and source/command association. Child exit 1 with valid expected SQLite may indicate findings; wrapper error/exit 1, signal, timeout, missing/invalid SQLite or child exit 2 is not findings. Preserve error and partial artifacts and diagnose before retry. Tool stage counts are neither source review completeness nor independent quality scores.

Final reporting retains original and final source hashes/diffs, complete failure/attempt ledger, protected oracle inventory, checkpoint decisions, all validation receipts, actual verdicts and locks, independent blind source reviews, cumulative costs and remaining opportunities. State limits honestly; do not call unreached work saturation or blocked work a pass.

## Operational priority comparison

Before the next production choice, apply [the broad residual-cost checkpoint](broad-residual-priority.md). Compare substantial changed-owner residuals and untouched responsibilities from the full live evidence, then record the concrete priority and actual characterization attempt. State whether a supervisor supplied the choice. Easier tests or a smaller interface alone do not justify indefinitely deferring a larger supported burden. This is an experimental readiness check; it does not replace protected validation or claim autonomous efficacy.
